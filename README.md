# OpenSpec Training

A practical introduction to spec-driven development with OpenSpec. The session demonstrates how to clarify intent, review a proposed change, implement it, and verify the result. It also discusses when the added documentation is worth the overhead.

## Learning outcomes

By the end of the session, participants should be able to:

- Decide whether a change merits an OpenSpec workflow or a direct edit.
- Explore ambiguous requirements and record decisions in a focused change.
- Review proposals, specs, and tasks for scope, correctness, and testability.
- Apply and verify a change, then sync and archive it when appropriate.

OpenSpec is a way to make important intent and decisions durable; it is not a requirement to spec every edit.

## Audience and Prerequisites

The session is for people interested in agent-assisted software development. Coding experience is helpful, but the examples use a simple HTML page.

Before the session, please:

1. Read the [OpenSpec getting started guide](https://github.com/Fission-AI/OpenSpec/blob/main/docs/getting-started.md).
2. [Install OpenSpec](https://github.com/Fission-AI/OpenSpec/blob/main/docs/installation.md).
3. Have Visual Studio Code and a GitHub Copilot license available for the guided demo and lab.
